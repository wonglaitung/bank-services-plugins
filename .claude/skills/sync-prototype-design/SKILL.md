# 同步原型设计到安全方案文档

将 `docs/mcp_prototype_sidecar.md` 中已验证的设计同步到 `docs/mcp_security_authentication.md`。

## 何时使用此技能

当以下情况发生时使用：

- 原型完成了新的功能验证
- 原型代码有重要修改
- 安全方案文档需要更新以反映原型验证结果

## 使用方法

### Windows

```cmd
%~dp0scripts\sync_prototype_design.py
```

### Linux/macOS

```bash
python3 .claude/skills/sync-prototype-design/scripts/sync_prototype_design.py
```

## 同步检查清单

执行此技能时，会检查以下同步项：

| # | 检查项 | 原型位置 | 方案位置 |
|---|--------|----------|----------|
| 1 | Sidecar 架构 | 第 2 节 | 第 4-5 节 |
| 2 | MCP 协议透传 | 第 3 节 | 第 8 节 |
| 3 | 身份注入机制 | 第 4 节 | 第 8-9 节 |
| 4 | FastMCP API 使用 | 第 5.3 节 | 第 10 节 |
| 5 | JSON-RPC 响应格式 | 第 5.3 节 | 第 10 节 |
| 6 | ContextVar 身份隔离 | 第 5.2 节 | 第 10 节 |
| 7 | 工具函数签名 | 第 5.4 节 | 第 3 节 |
| 8 | 错误处理模式 | 第 5.3 节 | 第 10 节 |

## 输出格式

同步报告包含：

1. **已同步项** - 原型和方案一致的内容
2. **待同步项** - 原型有但方案缺少或过时的内容
3. **同步建议** - 具体的修改建议

## 示例输出

```
==========================================
MCP 原型设计同步报告
==========================================

[已同步项]
✓ Sidecar 架构模式
✓ MCP 协议透传原理
✓ ContextVar 身份隔离

[待同步项]
△ 本地代理凭证解密流程 - 方案缺少启动流程图
△ 错误处理统一格式 - 方案代码示例不完整

[同步建议]
1. 在第 8 节添加本地代理启动流程图
2. 在第 10 节统一错误响应格式

==========================================
```

## 注意事项

- 同步前确保原型测试通过
- 同步后需要手动审查方案文档的修改
- 大的架构变更需要用户确认后再执行
